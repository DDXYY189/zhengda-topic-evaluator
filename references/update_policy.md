# 案例库更新与质量控制策略

## 1. 采用届次与年份双字段
正大杯届次与自然年份并非简单一一对应。每条数据至少保留：
- `edition`：第几届；
- `competition_cycle`：赛事启动年份或赛季；
- `award_announcement_date`：获奖公告日期；
- `group`：本科、研究生、专科、在华留学生等；
- `award`：国赛一等奖/二等奖/三等奖、公开赛冠军等，严格区分。

## 2. 来源分级
- A级：主办方发布的正式通知、获奖名单、评分细则。
- B级：承办高校、获奖高校官网或官方媒体发布的获奖信息。
- C级：第三方数据图谱、个人文章、论坛、视频资料。
不得用C级资料覆盖A级文件。

## 3. 信息完整度
每个案例单独记录：
- 题目是否可核验；
- 奖项是否可核验；
- 研究对象是否公开；
- 样本量是否公开；
- 调查方法是否公开；
- 统计方法是否公开；
- 结论是否公开；
- 完整报告是否可合法获取。

没有披露的字段填 `unknown`，不要猜测。

## 4. 版权和分发
- 公开网页链接可以作为参考来源；是否允许再分发全文要看原发布许可。
- 未经许可，不将完整参赛论文、购买资料、网盘文件或他人整理的付费资料嵌入公开 Skill。
- Skill 应优先存储自己的结构化案例摘要、引用链接和分析标签。
- 用户上传并拥有使用权的论文可作为私有知识库资料，但不得默认并入公共发行包。

## 5. 避免偏差
- 不能只收集一等奖；应适当收集二等奖、三等奖、未获奖但高质量的对照样本（若可合法获取）。
- 不能只研究本科组；不同组别的研究资源、深度和评审情境可能不同。
- 不能只分析标题；有完整报告时再分析抽样、问卷、模型、信效度、结论和建议。
- 不能从获奖案例直接推导“下届热门方向”。
- 需要按届次和组别控制比较范围。

## 6. 版本更新
每届官方通知发布后：
1. 保存原始文件和发布日期；
2. 提取赛事规则、组别、赛程、作品要求和评分表；
3. 与上一届规则做差异比较；
4. 更新 `competition-rules`，保留历史版本；
5. 不要因规则更新而重写案例库；
6. 对内部评分模型做“适配性复核”，但只有官方评分表明确变化时才调整官方对照维度。
